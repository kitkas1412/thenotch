# Tools

Detailed reference split out of [CLAUDE.md](../CLAUDE.md): System Monitor, Clipboard, Window Management and Quit on Close (`thenotch/Tools/`).

## System Monitor (`Tools/SystemMonitor/`, `ToolKind.systemMonitor`, off by default; public APIs only, no extra permission; temperatures and fan speeds aren't shown)

CPU, memory, network and disk.

- `SystemMetrics.swift` is pure (testable on plain values): `CPUUsage`/`CPUTicks`, `MemoryUsage` (active + wired + compressed pages), `NetworkRate`, `DiskUsage`, `MetricFormat` (decimal units) and `NetworkInterfaces`, which sums the `NET_RT_IFLIST2` counters of every interface that is up and not loopback, except those whose name starts with `lo`, `utun`, `ipsec`, `ppp`, `awdl`, `llw`, `bridge`, `ap`, `gif`, `stf`, `anpi`, `vmenet` or `feth` (virtual, tunnel and peer-to-peer interfaces, so VPN traffic isn't counted twice); `en*`, `pdp_ip*` and any other name count.
- `SystemReader` (an `actor`, `SystemCalls` holds the Mach/sysctl/volume calls) returns a `SystemSnapshot`.
- `SystemSampler` (`@Observable`, created by `AppDelegate` and passed as `ToolContext.systemMonitor`) publishes the snapshot and reads it every `interval` (1 s), only while `SystemSampling.shouldSample` holds: the tool is on (`isEnabled`, set by `SystemMonitorTool`'s start/stop), the menu panel is visible (`isPanelVisible`, set by `PanelWindowTracker` in `App/MenuPanel.swift` from the panel window's key, occlusion and close notifications) and `AmbientConditions.isVisible` (display awake, screen unlocked, session active; the lock state comes from the distributed `com.apple.screenIsLocked`/`screenIsUnlocked` notifications, there is no public API).
- Enabling seeds those conditions from `CGDisplayIsAsleep` and `CGSessionCopyCurrentDictionary`.
- The first reading only primes the deltas and isn't published; when sampling stops the snapshot is reset to empty, so the next open shows placeholders, not an earlier reading.
- `SystemMonitorSection` draws the top of the panel: CPU, memory, network down/up and disk free, each showing "—" until the second reading, then Open Activity Monitor.
- There are no settings: the Settings pane is the switch and short notes.
- The tool's UI is menu panel chrome, so it uses system fonts, colors and controls, not the Island tokens (see `DESIGN.md`).

## Clipboard (`Tools/Clipboard/`, `ToolKind.clipboard`, off by default; needs Notch on to be shown, and Accessibility only for the direct paste)

History of copies, kept encrypted on disk, shown in the island as a contributed module. `ClipboardTool` (`@Observable`; `ClipboardTool.current` is the running instance, for the menu panel and Settings) owns a `ClipboardStore`, `ClipboardMonitor` and `ClipboardPaster`, replaced by fresh empty ones on `stop()` so nothing stays in memory (the old store is `discard()`ed); it adds a `ClipboardIslandModule` to `IslandContributions` and registers `clipboard.showHistory` (⌃⌘V by default) only while `isHostAvailable` (the shortcut would do nothing without the island; `showHistory()` beeps if it can't open). The menu panel has a "Clipboard History…" row while Clipboard and Notch are on. Logs never contain clipboard content (only error types, `OSStatus` codes and counts).

- **Capture** (`ClipboardCapture`, pure): `ClipboardMonitor` polls `NSPasteboard.changeCount` every 0.5 s (no pasteboard notification exists; it never reads data without a change), only while running and `AmbientConditions.isVisible`; what was on the pasteboard at start isn't recorded, nor our own writes (`lastOwnChangeCount` plus a marker type, `AppIdentity.queueLabel("clipboard.own")`).
  - From the types of every item it first skips concealed/transient/auto-generated and password-manager types, own copies, Universal Clipboard copies when `clipboard.recordsRemote` is off, and ignored apps (frontmost app or `org.nspasteboard.source`; `clipboard.ignoredApps` holds bundle IDs).
  - Then it reads only what it needs, in this order of precedence: file URLs (paths only, every item), non-empty plain text (+ RTF/HTML), else an image (PNG, else TIFF).
  - Caps: plain text 1 MB (over it the copy is skipped, not recorded as an image), RTF/HTML 2 MB (dropped, the text kept), an image 10 MB. Never read: large or promised types such as `com.apple.webarchive`.
  - On macOS 15.4+ `accessBehavior` `.ask`/`.alwaysDeny` sets `privacyBlocked` and nothing is read (Settings explains how to allow it).
- **History** (`ClipboardHistory`, pure; `ClipboardStore`, `@MainActor`): newest or last used first, at most `clipboard.limit` entries (50/100/200/500, default 200) and 200 MB of images in total, oldest dropped; an entry with the same `contentHash` moves to the top instead of duplicating. Text and file entries live in the index; an image's bytes are a separate blob. Pasting (`markUsed`) moves an entry to the top.
- **Storage**: `ClipboardPersistence` writes `Application Support/<bundle id>/Clipboard/History.sealed` and `Images/<uuid>.sealed`: directories 0700 and files 0600, the directory excluded from backup, a symlink where a directory belongs is replaced, never followed; one serial queue runs every operation in order; the index is saved 1 s after the last change (`ClipboardStore.saveDelay`) and `saveNow()` flushes on quit and `stop()`.
  - `ClipboardCrypto` seals with AES-GCM: `TNCB`, version `0x01`, then the combined box; the associated data is the header, the role (`index` or `blob`) and the item's UUID, so a blob can't be swapped.
  - The 256-bit key is a generic password in the login keychain (`KeychainKeyStore`, service `<bundle id>.clipboard`, account `history-key`, not synced; the data protection keychain needs a Team ID), never in a file or log.
  - `ClipboardStore.load()` reads the key off the main thread; an index that can't be opened (other key, damaged) is deleted (`.startedFresh`); a key that can't be read keeps the saved files, the history lives in memory and `load()` retries (`.keyUnavailable`); `lastStorageIssue` has the messages Settings and the panel show.
  - `clear()` deletes the files and rotates the key (changes wait in memory until the new key exists); `clearNow()` does it synchronously and deletes the key, on quit and on `stop()` when `clipboard.clearOnQuit` is on (also at start, if a crash left files); `ClipboardTool.clearStoredHistory()` is Settings' Clear History while the tool is off.
- **UI** (`ClipboardIslandModule`): a tab (`takesKeyboard`, `excludesFromCapture`), 600 pt wide, `contentHeight` 216 (with the notch, the margin below it and the tab row it must fit `IslandController.panelSize`, 640×320); `hasExpandedContent` once the store is loaded and not empty; a new `ClipboardHistoryModel` per opening (and `ClipboardTool.historyOpened` remembers the frontmost app: where to paste).
  - `ClipboardHistoryView` (search field, one-line rows `ClipboardRow`, thumbnails in `ClipboardThumbnails`) uses the Island tokens and `.islandContentMargins()`, not literals.
  - Search is a case-insensitive, localized substring match within the first 10,000 characters of a text entry (`ClipboardHistoryModel.searchedCharacters`) or in a file entry's file names (last path component); images aren't searched.
  - Keys (`ClipboardHistoryModel.handle`): ↑/↓ move, Return pastes, ⌥Return pastes as plain text, ⌘⌫ deletes, ⌘1–9 paste the n-th row (by key code), Esc clears the search, then closes.
- **Paste** (`ClipboardPaster`): writes the entry back (with the own marker) after the island closed, then presses ⌘V (`CGEvent`) in the remembered app only if `clipboard.pastesDirectly` (default on), Accessibility is trusted, the target is alive, Secure Input is off, the target is frontmost (it is activated, up to 0.5 s) and the island panel isn't key (`maySendPaste`, pure). Otherwise it only copies and the island peeks 2 s (`LiveActivity` priority 55): "Copied — press ⌘V" (`.copied`); a missing image or file shows "Item no longer available". Plain text drops RTF/HTML; files as plain text become their paths.

## Window Management (`Tools/Windows/`, `ToolKind.windowManagement`, off by default; needs Accessibility, `AccessibilityPermission`, asked for when the tool is turned on in Settings)

- `WindowAction` has 17 actions, each with a default ⌃⌥ shortcut: arrows for halves, U/I/J/K for quarters, D/F/G/E/T for thirds, ↩ maximize, C center, and ⌃⌥⌘→/← for the next/previous display.
- `WindowLayout` is pure and works in Cocoa coordinates (origin bottom left): placements fill the screen's `visibleFrame` and are rounded to whole points; `axToCocoa`/`cocoaToAX` flip against the primary screen (the one whose origin is `.zero`). The window's screen is the one it overlaps most (`screenIndex`, else the nearest center).
- A display action keeps the window's relative position and size, scaled to the target (`movedToDisplay`), or fills the target's visible area if it doesn't fit.
- `WindowManagerTool` registers its hotkeys only while Accessibility is trusted: at start, on the Accessibility change notification (re-checked a second later, since the notification can arrive first) and on app activation; turning the tool off unregisters them.
- It beeps when there is no focused window or the move fails; full-screen windows, windows without a readable frame, and display actions with a single display do nothing.

## Quit on Close (`Tools/QuitOnClose/`, `ToolKind.quitOnClose`, off by default; needs Accessibility, `AccessibilityPermission`)

Quits an app a moment after its last real window closes. A missed quit is fine, a false one is not: every condition below must hold, and anything unreadable skips. Logs (category `quitOnClose`) hold only the bundle ID and the skip reason.

- **Gating** (`QuitOnCloseTool`): same pattern as Window Management. It watches only while Accessibility is trusted: at start, on the Accessibility change notification (re-checked a second later) and on app activation; without it, it detaches everything.
- **Watching** (`AppWindowWatcher`): one `AXObserver` per regular app (not ours), attached one at a time, 20 ms apart, so a hung app can't hold the main thread. An app that refuses is tried at most twice per pid (reset when the permission changes or the app launches). A newly launched app is attached after 1 s and retried once, 2 s later. The watcher tracks the app's real windows and tells when one is created or destroyed.
- **Scheduling**: a check is scheduled only when a tracked real window is destroyed, and cancelled when a window is created. It runs after `quitOnClose.delay` seconds (1, 2 or 5; default 2, `AppSettings.quitOnCloseDelays`).
- **Decision** (`QuitDecision.decide`, pure; `WindowInventory` holds the classification and the readers). It quits with `NSRunningApplication.terminate()` only if all hold:
  - The AX window list was read and has no real window (`WindowInventory.isRealWindow`: only `AXFloatingWindow` and `AXSystemFloatingWindow` don't count; a missing subrole does).
  - The CG window list (`CGWindowListCopyWindowInfo`, `.optionAll`; never window names, so no Screen Recording) has no window of the pid that is layer 0, alpha > 0, at least 40 pt on both sides, on a Space and ordered in. Both Space checks use private SkyLight functions looked up by name (`SLSCopySpacesForWindows`, `SLSWindowIsOrderedIn`, with `CGS` fallbacks); if they are missing or fail, the app is skipped (logged once).
  - Why both: AppKit keeps closed windows ordered out but still listed (TextEdit's 500x500 window; Spotify's closed main window keeps its Space but is ordered out), while windows on other Spaces or in full screen are ordered in. A field that is unknown counts as visible.
  - The app is running, finished launching, not hidden, regular and frontmost.
  - Its bundle ID isn't ours or in `QuitDecision.neverQuit` (Finder, Dock, SystemUIServer, NotificationCenter, Spotlight, loginwindow) and the mode allows it.
- **Settings** (`QuitOnClosePane`): `quitOnClose.mode` (`QuitOnCloseMode`: all except the listed apps, the default, or only the listed apps) and `quitOnClose.apps` (bundle IDs).
- **Limit**: `kAXWindowsAttribute` doesn't list windows on other Spaces. Apps that should keep running without windows (music players, downloads) belong in the exclusion list.
